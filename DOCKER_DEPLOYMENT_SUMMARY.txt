HOW IT WORKS (Data Flow)
================================================================================

Without Host Volumes (❌ OLD):
  Django writes → Docker managed volume → Only accessible via docker exec
  Nginx wants to serve static → Can't access, needs to proxy through Django

With Host Volumes (✅ NEW):
  Django writes → /app/staticfiles → /home/ec2-user/.../staticfiles → Nginx reads directly
  Avatar upload → /app/media → /home/ec2-user/.../media → Always visible on host

================================================================================
DEPLOYMENT WORKFLOW
================================================================================

STEP 1: Prepare Host (Run on EC2 as ec2-user)
  bash DOCKER_HOST_SETUP.sh
  → Creates: staticfiles/, media/, postgres_data/ directories

STEP 2: Configure
  Edit .env.prod with your values:
    DB_NAME=onlinepharmacy_prod
    SECRET_KEY=your-very-long-random-string
    ALLOWED_HOSTS=yourdomain.com
    etc.

STEP 3: Build & Start
  docker compose -f docker-compose.prod.yml build
  docker compose -f docker-compose.prod.yml up -d

STEP 4: Initialize
  docker compose exec web python manage.py migrate
  docker compose exec web python manage.py collectstatic --noinput
  docker compose exec web python manage.py createsuperuser

STEP 5: Verify
  ls -la /home/ec2-user/OnlinePharmacy/staticfiles/static/   ← See static files
  curl http://localhost:8000/api/v1/health/                 ← Check API
  curl http://localhost:8000/static/css/main.css             ← Check static

STEP 6: (Optional) Add Nginx
  mkdir nginx && create nginx/nginx.conf
  Uncomment nginx service in docker-compose.prod.yml
  docker compose up -d nginx

================================================================================
VOLUME MOUNT EXPLANATION
================================================================================

What is a Volume Mount?
  A way to map a directory INSIDE the container to a directory ON THE HOST.

In docker-compose.prod.yml:
  volumes:
    - /home/ec2-user/OnlinePharmacy/staticfiles:/app/staticfiles
    ├─ /home/ec2-user/.../staticfiles  = HOST PATH (on EC2)
    └─ /app/staticfiles                 = DOCKER PATH (inside container)

What this means:
  1. When Django code does: file.save('/app/staticfiles/file.txt')
  2. File is actually saved to: /home/ec2-user/OnlinePharmacy/staticfiles/file.txt
  3. You can SSH to EC2 and see the file immediately
  4. No docker export, no volume management, just regular files

Why this is good:
  ✅ Easy backups (just copy /home/ec2-user/OnlinePharmacy/)
  ✅ Easy recovery (restore files, restart Docker)
  ✅ Easy scaling (multiple containers can access same files)
  ✅ Easy debugging (look at files directly)

COMMON SCENARIOS
================================================================================

Scenario 1: Upload an avatar
  1. User clicks upload in /account/
  2. Django receives file
  3. Django saves to /app/media/uploads/avatars/
  4. That writes to /home/ec2-user/OnlinePharmacy/media/uploads/avatars/
  5. You can SSH and see: ls -la /home/ec2-user/OnlinePharmacy/media/uploads/avatars/
  6. File is there! ✅

Scenario 2: Nginx serving static CSS
  1. Browser requests /static/css/main.css
  2. Nginx looks in /app/staticfiles/static/css/main.css
  3. Due to volume mount, that's /home/ec2-user/.../staticfiles/static/css/main.css
  4. Nginx reads and serves to browser
  5. Django never involved! ✅ (faster)

Scenario 3: Backup all data
  1. Stop containers: docker compose down
  2. Copy files: tar -czf backup.tar.gz /home/ec2-user/OnlinePharmacy/
  3. Upload to S3/Google Cloud
  4. Done! ✅

Scenario 4: Restore from backup
  1. docker compose down --volumes
  2. Restore: tar -xzf backup.tar.gz -C /
  3. docker compose up -d
  4. Done! All data restored ✅

MIGRATION PATH (From Old Setup)
================================================================================

If you already have docker-compose running with volumes:

OPTION A: Clean migration (data loss - for testing)
  1. docker compose down -v                    (delete all)
  2. Update docker-compose.prod.yml           (new volume config)
  3. bash DOCKER_HOST_SETUP.sh                (create directories)
  4. docker compose build && up -d            (start fresh)

OPTION B: Preserve data (recommended)
  1. Backup everything: docker compose exec db pg_dump ... > backup.sql
  2. docker compose down                      (but keep data)
  3. Update docker-compose.prod.yml           (new volume config)
  4. bash DOCKER_HOST_SETUP.sh                (create directories)
  5. Copy database back: docker compose exec db psql ... < backup.sql
  6. docker compose up -d                     (start)

  DEBUG=False
  SECRET_KEY=<64-char-random-string>

  SECURE_SSL_REDIRECT=True
  SESSION_COOKIE_SECURE=True
  CSRF_COOKIE_SECURE=True

PATHS (should match docker-compose):
  MEDIA_ROOT=/app/media
  MEDIA_URL=/media/
  STATIC_ROOT=/app/staticfiles
  STATIC_URL=/static/

CACHE:
  REDIS_URL=redis://redis:6379/0

TESTING DEPLOYMENT
================================================================================

After running: docker compose -f docker-compose.prod.yml up -d

Test 1: Services running?
  docker compose ps
  Expected: All containers have status "Up"

Test 2: Database ready?
  docker compose logs db | head -20
  Expected: "database system is ready to accept connections"

Test 3: Web app running?
  docker compose logs web | head -20
  Expected: No errors, "Started server process"

Test 4: Static files collected?
  ls -la /home/ec2-user/OnlinePharmacy/staticfiles/static/
  Expected: See admin/, css/, js/, images/ directories

Test 5: API responding?
  curl -I http://localhost:8000/api/v1/health/
  Expected: HTTP/1.1 200 OK

Test 6: Static files serving?
  curl -I http://localhost:8000/static/css/main.css
  Expected: HTTP/1.1 200 OK (or 304 Not Modified)

Test 7: Admin accessible?
  curl -I http://localhost:8000/admin/
  Expected: HTTP/1.1 302 Found (redirect to login)

If any test fails, check:
  1. docker compose logs <service-name>
  2. Check permissions: chmod -R 755 /home/ec2-user/OnlinePharmacy/
  3. Check disk space: df -h /home/ec2-user/

SUPPORT & TROUBLESHOOTING

Problem: Container won't start
  Solution: docker compose logs web
  Then check: Is .env.prod correct? Is Docker running?

Problem: Static files 404
  Solution: docker compose exec web python manage.py collectstatic --noinput
  Then: ls -la /home/ec2-user/OnlinePharmacy/staticfiles/static/

  Solution: mkdir -p /home/ec2-user/OnlinePharmacy/media

Problem: Database connection error
  Solution: docker compose logs db
  Check: Is DB_PASSWORD same in both POSTGRES_PASSWORD and DB_PASSWORD?
